Optimization

High-level optimization interface and gradient computation.

Main Interface

DistributedEmitterOpt.optimize! — Function
optimize!(prob; kwargs...) -> (g_opt, p_opt)

Run topology optimization with beta-continuation.

Keyword arguments:

  • max_iter – iterations per beta value (default 40)
  • β_schedule – projection steepness values to sweep
  • α_schedule – optional loss schedule (same length as beta_schedule)
  • use_constraints – enable linewidth constraints on the final beta epoch only
  • tol – relative tolerance for convergence
  • backup – enable autosaving (p, g_history) checkpoints
  • backup_every – autosave interval (iterations)
  • backup_path – optional checkpoint path (default joinpath(prob.root, "results_backup.jld2"))
  • resume_from – optional checkpoint path to resume from
  • constraint_scale – multiply constraint values, gradients, and tolerances by this factor (default 1.0, no-op). A pure reparameterization: the feasible set is unchanged. Set large (e.g. 1e8) for constrained β=Inf epochs, where the raw constraint terms (~1e-6) are otherwise below one ULP of the objective inside the CCSA dual and the dual line search fails (ret=-1). Known issue at constrained β=Inf, independent of this fix: each epoch resets CCSA ρ and σ to defaults, discarding the previous epoch's learned trust-region state.
  • constraint_tol_raw – absolute tolerance on each plain-path linewidth constraint M - b1 (default 1e-8, preserving legacy behavior). For an EPS-relative tolerance use e.g. 0.01 * prob.control.b1. Multiplied by constraint_scale in the standalone foundry path. Stored and checked on resume; epigraph mode has its own tolerances.
  • ccsa_verbose – verbosity level passed through to the standalone CCSA backend
  • dual_algorithm – solver for the standalone backends' CCSA dual subproblem: :mma (default, as in upstream NLopt) or :lbfgs (Luksan PLIS). Ignored by backend=:nlopt. The choice is not stored in the checkpoint; a run may resume under either solver.
  • robust_samples – nothing, or a vector of (slope, z0) sidewall samples to take the worst case over
  • robust_sharpness – KS sharpness, relative to the flat-substrate normalization (default 200); must be > 0, and Inf takes the exact minimum
  • robust_mode – how the worst case is aggregated: :ks (default; KS softmin with robust_sharpness, fixed scale gnorm) or :epigraph (standalone backends only; one constraint per sample, see EpigraphSidewall.jl and `runepochstandalone_epigraph!`)
  • epigraph_sigma – initial CCSA σ of the epigraph variable τ (default 1.0)
  • epigraph_tol – CCSA tolerance of the epigraph constraints τ − gᵢ/(g_norm T) ≤ 0
  • epigraph_linewidth_tol – tolerance of the NORMALIZED linewidth constraints M/ε − 1 ≤ 0 in epigraph mode (requires constraint_scale == 1/b1)
  • on_infeasible – what to do when use_constraints is set and the returned design violates a linewidth constraint beyond its tolerance: :warn (default; log a warning with both constraint values and return the design) or :error (throw). Either way the design is already in prob.p and, with backup, in the final checkpoint.

Returns the final accepted design of the last epoch and its normalized objective, not the best objective seen (prob.g_best/prob.p_best, which can come from an earlier β or an infeasible trial). With use_constraints, both linewidth constraints are re-evaluated at the returned design after the last epoch (linewidth_feasibility); a CCSA return does not by itself guarantee feasibility, e.g. after max_iter runs out.

Checkpoints store the accepted design's objective, the flat-substrate normalization and, for standalone runs with constraints, constraint_scale. An exact resume reuses the stored normalization and refuses a different constraint_scale; resuming a checkpoint whose epochs are all complete restores the last epoch's β and loss before returning.
